# טלגרם — חוקים תפעוליים של ערוץ התקשורת

**מקור:** מחקר ארכיטקטורה שיובל הביא (19.9.2026) על פלטפורמות הודעות דו-כיווניות בעלות אפס.
**סטטוס אימות:** ⚠️ המספרים והמגבלות בקובץ הזה **לא אומתו עצמאית** מול התיעוד של Telegram.

---

## מה המחקר אישר

המחקר בחן את כל השוק ופסל את אותם מועמדים שנפסלו גם אצלנו, מאותן סיבות. **החלק הזה עדיין תקף** — הוא מונע פתיחה מחדש של וואטסאפ ושל ספקי ההודעות:

| מועמד | למה נפסל |
|---|---|
| WhatsApp Cloud API | מחייב חשבון Meta Business וכרטיס אשראי. בנוסף — איסור מ-2026 על בוטים בעלי אופי שיחה כללי, וזה בדיוק מה שאנחנו בונים |
| WhatsApp לא רשמי (Baileys) | חסימת חשבון. לפי המחקר נחסמו כ-6.8 מיליון חשבונות ב-2025 |
| Twilio / Vonage / MessageBird / Plivo | אין Free Tier קבוע. כרטיס אשראי חובה |
| ספקי SMS ישראליים | אין API דו-כיווני חינמי |
| Signal (signal-cli) | אין כפתורים מובנים. דורש Daemon מקומי ורישום SMS |

חלופות שנשארו על השולחן במחקר: **Discord** ו-**Slack Socket Mode**. ⛔ **לא רלוונטיות יותר** — הערוץ הוא האפליקציה, ולא מחפשים ערוץ צ'אט חלופי.

---

## ⛔ בטל — קבצים ומדיה

| מגבלה | ערך |
|---|---|
| הורדת קובץ על ידי הבוט | 20MB |
| העלאה מהמשתמש לבוט | 50MB |
| Local Bot API Server | עד 2GB |

**כלל האחסון שהיה:** שרתי Telegram שומרים כל קובץ ללא הגבלת זמן ומנפיקים מזהה יציב (`file_id`). המערכת הייתה שומרת את המזהה ב-`sources` ושולפת דרך `getFile` — אפס אחסון, אפס טוקנים.

⛔ **זה מה שנשבר.** הפער נרשם ב-`06-db-schema.md` ובשאלות הפתוחות. **אין להוסיף שדה `file_id` לסכמה** — הוא היה מזהה של טלגרם.

---

## ⛔ בטל — כפתורים ומנגנון האישור

טלגרם תומכת ב-`InlineKeyboardMarkup`, ולחיצה מייצרת `CallbackQuery`. שדה ה-`callback_data` מוגבל ל-64 בתים, ולכן הכפתור היה נושא **מזהה בלבד** — מזהה השורה ב-`messages` — והמערכת הייתה שולפת ממנו את הפעולה המלאה.

⛔ **בטל.** ספארי באייפון מתעלמת מ-`actions` לחלוטין. ההתראה יכולה רק לפתוח מסך, והאישור קורה בתוך האפליקציה.

**מה כן נשאר מזה:** המבנה במסד. שורת `messages` עם `awaiting_reply = true`, `entity_type`/`entity_id` ו-`expires_at` נכונה כמו שהיא — רק דרך המענה השתנתה.

## ✅ עדיין תקף — דחיית ההרצה המקומית

המחקר המליץ על **הרצה מקומית במחשב של יובל** — Long Polling, Cron מקומי, SQLite. נדחה:

| נושא | המלצת המחקר | ההחלטה שלנו |
|---|---|---|
| איפה רץ | תהליך מקומי במחשב | Vercel Function + Workflow |
| קבלת הודעות | Long Polling | Webhook |
| תזמון | Cron מקומי | Vercel Workflow עם המתנה מדויקת |
| מסד | SQLite מקומי | Neon (Postgres) |

**הנימוק, ותקף גם היום:** המחקר מניח מחשב דלוק תמיד, וזה האילוץ שנפסל מלכתחילה. המחקר עצמו מודה: *"אם המחשב כבוי או מנותק מהרשת, הודעות תזכורת לא יישלחו בזמן."*

---

## ✅ עדיין תקף — מה לא רלוונטי לנו

- **Cloudflare Tunnel / Render.com** — פתרונות מעקף למי שמריץ מקומית. Vercel נותן HTTPS מובנה.
- **GitHub Actions כ-Cron** — נפסל במחקר בגלל עיכובים של 15 דקות עד 4.5 שעות.
- **n8n / Zapier / Make / Pipedream** — שכבת אוטומציה מתווכת. המערכת כותבת את הלוגיקה בעצמה.

מארבעת פריטי האימות שהיו כאן, שלושה בטלים (מגבלות טלגרם) ואחד עבר: **Webhook מול Vercel — האם יש דרישות תעודה או IP שלא נבדקו.** הוא רשום כעת ב-`03-app-channel-rules.md`.
