### M.2 סיכום יומי בצ'אט וסימון בכפתורים (תלוי בצ'אט, שלב 8.2א ב-`35`)
- **קבצים:** `db/schema.sql` (שינוי: הוספת `intake_checks`), קוד הצ'אט (ייקבע בתכנון 8.2א), בדיקות.
- **מבנה `intake_checks`** `[הסקה]`: `id` uuid · `outcome_id` uuid REFERENCES `intake_outcomes(id)` · `verdict` text (`right` / `wrong` / `was_event` / `not_event`) · `checked_at` timestamptz. שורה אחת לכל סימון, בלי עדכון.
- **התנהגות מצופה** (קריטריוני הקבלה המדויקים ייכתבו בסיכום השלב, אחרי שהצ'אט מאושר, ויאושרו על ידך):
  1. פעם ביום, אם יש הודעות שלא סומנו, מופיע בצ'אט סיכום אחד.
  2. לכל פריט: מה נרשם (סוג · מקצוע · תאריך) או "לא נתפס", וקטע קצר מההודעה כדי שתדע על איזו מדובר. הטקסט מוצג רק בתוך האפליקציה.
  3. על "נרשם": כפתורים **נכון** / **לא נכון**. על "לא נתפס": **זה אירוע** / **לא אירוע**.
  4. כל לחיצה מוסיפה שורה ב-`intake_checks`. פריט שלא נענה פוקע (H1).
- **plan B:** אם הצ'אט לא מוכן, פעם בשבוע בסשן עם Claude: Claude קורא את ההודעות שלא נתפסו ב-SELECT (קריאה בלבד), מסכם בלי שמות וטלפונים (`24-working-with-yuval.md:192`), ואתה מאשר.

## 9. קריטריוני סגירה
1. `intake_outcomes` ו-`intake_checks` קיימות במסד החי, ו-`schema-compare.mjs` מראה שהן זהות לקובץ.
2. תוצאת העיבוד נרשמת לכל הודעה שהועברה במשך 14 ימים רצופים (אפשר לספור: שורה אחת לכל מקור).
3. יש דוח אחד שמחשב, מתוך ההודעות שסומנו, ומציג יחד עם מספר ההודעות (n):
   - **החמצה** = `was_event` ÷ (`was_event` + `right`).
   - **רישום שגוי** = `wrong` ÷ (`wrong` + `right`).
   - **כיסוי** = `recorded` ÷ (`recorded` + `unclassified` + `failed`).
4. יובל מכריע והכרעתו נרשמת ב-`45`: להישאר בקוד בלבד, או לחזור לשאלת שכבות ניקוי השמות. **הסף ל"מחמיץ יותר מדי" לא הוגדר; יוגדר בהכרעה הזו, על סמך הנתונים.** נקודת התייחסות בלבד: יעד הסיווג הזמני 90% ב-`35` (סעיף "קריטריוני סגירה") `[מקור: 05-open-questions.md:556]`.
5. אין קריאה ל-AI בנתיב הקליטה (אותה בדיקת `grep` משלב M.1).
