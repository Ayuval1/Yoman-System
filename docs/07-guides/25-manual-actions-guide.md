# 25 — מדריך הפעולות הידניות של יובל

> **למה:** יש פעולות שרק יובל עושה (סודות, תנאי שימוש, יצירת חשבון). בשלבים 1 ו-2 הוא שאל שבע פעמים "איפה / איך / מה לבחור". המדריך הזה נותן את הצעדים עם השמות כפי שהם מופיעים אצלו.
> **מקור:** שיחות 5-6.10.2026 וצילומי המסך של יובל. כל שלב מסומן: **נראה** = נראה בצילום של יובל, **דיווח** = יובל אמר שעשה, **לא אומת** = לא נראה ולא נבדק.
> **כלל:** אם משהו אצלך נראה אחרת מהכתוב כאן, מצלמים מסך (בלי סודות!) ולא מנחשים.
> **סודות:** לא כותבים אותם בצ'אט ולא בקבצים (`CLAUDE.md:118`). לפני צילום מסך של שדה עם סוד, מכסים אותו.

## 1. להוסיף משתנה סביבה (סוד) ב-Vercel
הדרך: Vercel ← הפרויקט `yoman-system` ← Settings ← Environment Variables ← **Add Environment Variable**. (**נראה** בשלב 1.)

| שדה | מה לעשות |
|---|---|
| **Key** (שם) | להעתיק בדיוק, באותיות גדולות: `INTAKE_SECRET` או `CRON_SECRET`. את השם לא ממציאים |
| **Value** (ערך) | מחרוזת אקראית ארוכה (30 תווים ומעלה), שאתה ממציא. **ל-`CRON_SECRET` ערך שונה** מזה של `INTAKE_SECRET`. לא שולחים אותה לאף אחד |
| **סוג** | **Secret** (העיגול הכחול, כבר מסומן). **לא Config**, כי Config קריא אחרי שמירה |
| **Environments** | `Production` (בשלב 1 סומנו Production ו-Preview; בפועל הסודות קיימים רק ב-Production, ובענפי Preview הקליטה מחזירה 401) |
| **Save** | ללחוץ שמירה. אותו דבר עם המשתנה השני |

- **אחרי השמירה אי אפשר לראות את הערך שוב** (לפי ההסבר בשיחה; **לא אומת מול התיעוד של Vercel**). לכן **שומרים את `INTAKE_SECRET` בצד** (למשל בהערות בטלפון), כי מקלידים אותו בקיצור.
- **אם הערך אבד:** מוחקים את `INTAKE_SECRET` ויוצרים מחדש עם ערך חדש, ואז Redeploy (סעיף 2) ועדכון הקיצור.
- **משתנים חדשים נכנסים לתוקף רק אחרי Redeploy.**

## 2. Redeploy (פריסה מחדש)
בשלב 1 נעשה דרך Chrome על ידי Claude (לחיצה על Redeploy על הפריסה הנוכחית של Production, והפריסה עלתה `READY`). **איך יובל עושה את זה בעצמו: לא אומת.** אם צריך: לבקש מ-Claude, או לצלם את דף Deployments.

## 3. לבדוק שהמערכת קלטה (בלי להבין קוד)
- בקיצור: וי ב-Dynamic Island = הצלחה (**בתנאי שיש בקיצור פעולה שבודקת "התקבל"**, ראה `26-shortcut-recipe.md`). בלי הבדיקה, וי מופיע גם כשהשרת דחה.
- הבדיקה האמיתית: Claude בודק לוגים ומסד (`reference/ops-commands.md` בסקיל).
- לבדיקה עם הסוד מהמחשב: Claude נותן פקודת PowerShell שמבקשת את הסוד בהקלדה מוסתרת. **יובל מריץ, לא Claude.**

## 4. ליצור מסד Neon (נעשה בשלב 1; לא חוזרים על זה)
Vercel ← Storage (`https://vercel.com/yuval-amars-projects/yoman-system/stores`) ← Create Database ← **Neon** ← Continue. (**נראה**.) מה נבחר:
- **Region:** Washington, D.C. (East), `iad1`, כמו הפונקציות.
- **Auth:** כבוי.
- **Plan:** Free (בלי כרטיס אשראי). **לא ללחוץ על Launch או Scale** (בתשלום).
- **שם:** `neon-orange-anchor` (ברירת מחדל).
- חיבור לפרויקט `yoman-system`, **Custom Prefix ריק**, Sensitive דלוק. התוצאה: `DATABASE_URL` נוצר לבד.
- **"Accept and Create"** (תנאי שימוש) אתה מאשר בעצמך. Claude עוצר לפני.
- **עוצרים אם מופיע מחיר או כרטיס אשראי** (אין תקציב).

## 5. להריץ שאילתה ב-Neon
Vercel ← Storage ← `neon-orange-anchor` ← **Query**. (**נראה**.)
- **פקודה אחת בכל הרצה.**
- בשאילתות קריאה ("select") משאירים את **Read-only** דלוק.
- השאילתות המוכנות: `reference/ops-commands.md` בסקיל, סעיף 4.

## 6. להריץ את הקיצור
- **מתפריט השיתוף**, לא מ-▶. (**נראה**.)
- Notes: מסמנים טקסט ← Share ← `יומן-בדיקה`.
- הקיצור לא מופיע ברשימה? בתחתית תפריט השיתוף: **עריכת הפעולות** ומפעילים אותו. (**נראה**.)
- בהרצה הראשונה בוחרים **"קבוע"** בהרשאה.
- **וואטסאפ:** לחיצה ארוכה על הודעה ← אפשרות Share (**דיווח**: הקיצור רץ משם; **איפה בדיוק האפשרות: לא נראה בצילום**).
- **לשלוח לבדיקה רק הודעה שלך** (למשל לצ'אט "אתה" או לקבוצת בדיקה), לא הודעה פרטית של מישהו אחר.

## 8. החלפת סוד (פתוח, לא בוצע)
